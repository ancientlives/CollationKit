Name

CollationKit

collationkit — transposition-aware scholarly textual collation, with citations.

Synopsis

collate                                       # interactive menu
collate run [options] base witness …           # scriptable
collate run --dir folder --all --out results   # + collation.html viewer
collate run --strategy peer-msa --lexicon fr-en.lex fr.txt en1.txt en2.txt

Description

Scholars who study a work that survives in several forms (a manuscript, corrected proofs, a first edition, a revised edition, rival translations) need to know precisely how those versions differ. This is textual collation, and its product is an apparatus criticus: a citable record of every variant, located by page, line and word.

CollationKit is a deterministic, pure-Swift engine for that job. Given several witnesses of one work, it reports every insertion, deletion, substitution and transposition, including a passage that moved across a page boundary. Each finding carries a citation. It separates substantive changes of wording from accidentals (spelling, punctuation, case). It merges many witnesses into one variant graph, with or without a privileged base text, and can anchor witnesses across languages.

It ships with the collate command-line tool, a self-contained interactive HTML viewer, a language-neutral conformance corpus with a JSON Schema, and a corpus of complete novels in rival translations for evaluation.

Why not diff

Words, not lines
Prose reflows, and revision happens at the level of the word and phrase. Alignment is Needleman–Wunsch over tokens, so a reworded clause is one substitution rather than a deleted block plus an inserted block.
Moves are moves
An anchor and transposition pass recognises a passage that was relocated, even across a page and even when revised in transit, and reports it once, as a move with certain or likely confidence.
Not every difference matters equally
Normalisation separates substantive variants from accidentals, so a GB/US spelling change doesn't drown the finding. Accidentals can be recorded on request for a diplomatic view.
The output is a citation, not a patch
Every variant is located: p. 2 · line 1 · words 1–10, under an explicit pagination model.

Example

Excerpt from the located variant report for two witnesses of the bundled six-edition example, the manuscript (MS) and the Uniform edition (UNI):

$ collate run MS.txt UNI.txt
MS vs UNI: 5 variant(s)
  [1] TRANSPOSITION (moved)  (ACROSS PAGES)
      MS:  “The lamps were lit along the quay one by one” @ p.2 · line 1 · words 1–10
      UNI: “The lamps were lit along the quay one by one” @ p.1 · line 2 · words 1–10
  …
  [4] SUBSTITUTION
      MS:  “tired”  @ p.1 · line 2 · word 3
      UNI: “weary”  @ p.1 · line 3 · word 3
  [5] SUBSTITUTION
      MS:  “cold”   @ p.2 · line 2 · word 2
      UNI: “bitter” @ p.2 · line 1 · word 2

A line diff would report the moved sentence as a deletion on page 2 and an unrelated insertion on page 1.

Installation

Requires macOS 13 or later and Swift 5.9+ (Xcode 15 or later). No third-party dependencies.

git clone https://github.com/ancientlives/CollationKit.git
cd CollationKit
swift test                    # 222 tests
swift build -c release        # use release builds for full-length texts
.build/release/collate run --dir corpus/verne/journey-centre-earth --all --out results
open results/collation.html

Research

The deterministic core is mature and evaluated on complete novels in independent translations, on verse, and on non-Latin scripts. The open questions are above it and around it:

A semantic layer, carefully gated
Can learned signals such as sentence-level cross-language anchoring or corpus-wide phrase commonness sharpen alignment and move confidence, while keeping the engine deterministic, auditable and faithful to each witness's own words?
The irreducible residual
Short passages that sit near their original position can't be told from coincidence by geometry alone. Word and phrase rarity have already been shown not to help (a documented negative result). What can?
Visualisation and trust
The viewer's design is argued from principles but hasn't been evaluated with users. Which views do scholars rely on? Does the alignment map let a reader verify an alignment? How should calibrated uncertainty be shown to an expert who is entitled to overrule the tool?

Read the research introduction for the full picture. Two papers are in preparation, one on the collation algorithms and their evaluation and one on visualising collation results.

Contributing

Contributions of code, evaluation texts, bug reports and research questions are welcome through pull requests. Read CONTRIBUTING.md for the workflow and the engine's invariants: purity, determinism, and never hand-editing a golden. A collation that looks wrong on a real text is useful evaluation data, so please open an issue.
